## 5. Phase 5 명세: 공인중개사 블라인드 피드 대시보드 (`/agent/feed`)

> 순서상 "다음 작업" 1~4 이후. 착수 전 대표님과 크레딧·쿼터 정책 재확인.

1. **타겟 사용자**: 관리자 승인이 완료된 다산동 파트너 공인중개사 (주 영업 대상: 매물이 있는 단지 내 부동산을 제외한 모든 중개사)
2. **화면 구성**:
   - **상단 헤더**: 중개사무소 정보, 크레딧 남은 개수 (하루 쿼터는 2026-10-29 대표님 결정으로 없앰)
   - **블라인드 매물 피드 카드**: `[단지] 평형 10*동 ***호 · 고층`, 희망가, 집주인 제안 복비, 추가 보수, 옵션/특이사항, 점유 상태
   - **매물 상세**: `BrokerPayoutCard`(중개사가 받는 금액 = 제안 복비 + 추가 보수) — 집주인 화면에서 내린 카드를 여기서 사용. 문구는 `siteContent.analysis.brokerPayout`
   - **소유자 확인 (허위매물 B안, 2026-10-24 확정)**: 매칭 확정 후 중개사 화면에 "등기 소유자 일치 / 불일치" 버튼. 중개사는 계약 전 등기 확인 의무(공인중개사법)가 있으므로 그 결과를 기록만 받는다. 불일치 → 의뢰 즉시 중단, 집주인 이용 정지(약관 제11조), 해당 매칭 크레딧 환불(약관 제10조). 기록 필드 `ownership_check { status: 'MATCH' | 'MISMATCH', checked_at, broker_id }`
   - **[매칭 요청하기]**: 크레딧 차감, 합의 조건 확인 팝업, 요청 시 집주인 `/my-requests`에 `AGENT_REQUESTED` 상태 전달. 선택받지 못하거나 계약하지 못해도 크레딧 환불 없음을 명확히 고지
   - **정책값 보정용 기록 (2026-10-24 합의)**: 의뢰마다 `recommended_discount`(의뢰 시점 고정값) · `proposed_discount`(집주인 실제 제안, 추가 보수 포함) · `area_band` · `speed_ratio` · `broker_request_count` · `first_request_at`(첫 요청까지 걸린 시간). 할인 구간별 요청률로 20/30/50%·노랑 폭을 월 1회 보정
3. **가드레일 준수**:
   - 모든 텍스트는 `src/config/siteContent.ts`에 신규 키(`brokerFeed`)로 SSOT 관리
   - 시맨틱 토큰만 사용, 360~390px 가로 스크롤 금지, 터치 타깃 44px
   - 민감 필드(동·호수, 연락처)는 매칭 확정 전 응답에서 제외 (백엔드 연동 시 RLS + 소유권 검증)
   - 작업 완료 후 `npm run typecheck`·`npm test` 통과, 빌드는 별도 복사본에서
