## 2. 명단 데이터 (`data/brokers/다산동 부동산_20261024.xls`)

엑셀 BIFF 형식, 머리글이 한 칸씩 밀려 있음 → 실제 순서 `등록번호|대표자|상호|주소|전화|상태`. 분석 결과:

| 항목 | 값 |
|---|---|
| 행 수 | 336 (영업중 335, 휴업 1) |
| 등록번호 형식 | `41360-YYYY-NNNNN` 298 · 옛 형식 `가3622-08-04` 34 · 기타 4 (`36132004-41`, `53`, `413102009-0098`, `413102011-0077`) |
| 등록번호 중복 | 0 → 등록번호를 기본 키로 쓸 수 있음 |
| 전화 없음 | 73 (`-` 43 + 빈칸 30). 이 중 5곳은 상호 안에 번호(`다산(564-4600)…`) → 확인 전화 가능, 나머지 **68곳은 네이버 부동산 광고 번호로** (§7-1) |
| 법인 (`(주)`·`법인`) | 6 — 대표자 = 법인 대표 |
| 2016년 이전 개설 (표준 형식 기준) | 3 — 옛 형식 34곳은 연도를 확정할 수 없음 |

- 대표자 이름·전화가 들어 있으므로 **서버 전용**으로 둔다 (화면 번들에 넣지 않음). `scripts/build-broker-registry.mjs`가 CSV → `data/brokers/dasan-offices.json` 생성, 서버 액션에서만 읽음
- 원본 xls는 엑셀에서 CSV(UTF-8)로 저장해 `data/brokers/`에 함께 둔다 (변환 도구 의존성 없이)
- 갱신: 월 1회 새 명단으로 다시 생성. 이미 가입한 곳이 휴업·폐업으로 바뀌면 요청 보내기 정지

## 3. 기준점 (Baseline)

| 서비스 | 인증 방식 | 복비에 가져올 것 |
|---|---|---|
| 짐싸 | 자격 서류 확인 + 대면 인터뷰, 면허증 기반 연차 표시 | 공적 자료 기반 사실만 파랑 배지로 |
| 직방 아파트PRO | 등록 중개사만, 대표 이름·사진 공개 배너 | 등록 대조는 같고, 공개는 하지 않음 (블라인드) |
| 공공 데이터 | 국토부 부동산중개업사무소정보(등록번호·대표자·상태). 공개 자료라 "실시간 아님" 주의 | 명단 대조는 **공개 정보라 본인 증명은 못 됨** → 별도 소유 확인 필요 |

핵심: 등록번호·대표자·상호는 누구나 VWorld에서 볼 수 있는 공개 정보다. 대조만으로는 "그 사무소 대표 본인"임을 증명하지 못한다.

## 4. 흐름 (헤이딜러식 한 화면 한 질문)

1. **사무소 확인**: 등록번호 · 대표자 · 상호 3칸 입력 → 서버에서 대조 (3칸을 다 받은 뒤 대조: 등록번호만으로 사무소 이름을 보여주면 조회 도구가 됨)
2. **휴대폰 인증**: 대표 휴대폰 OTP (Supabase Auth, 지금은 목업)
3. **강점 칩**: 최대 3개 (`SITE_CONTENT.brokerStrengths`)
4. **약속 확인**: 매칭 후 48시간 안 광고 등록, 계약 48시간 안 보고, 합의 복비 지키기, 블라인드(매칭 전 연락처·상호 노출 금지) — 기존 법적 서약 모달 문구 재사용·정리
5. **접수 완료**: 확인 코드 표시 → 관리자 확인 전화(§7-1) 후 승인 → 요청 피드 열림

## 5. 대조 규칙 (결정론, 순수 함수 `matchBrokerOffice`)

정규화:
- 등록번호: 공백·`제`·`호` 제거, 하이픈류(–—‐) → `-`
- 대표자: 공백 제거
- 상호: 공백·괄호 안 내용(`(555-2442)`)·`(주)`·`주식회사`·꼬리말(`공인중개사사무소`·`부동산중개법인`·`부동산중개`·`공인중개사`·`부동산`) 제거

판정 (등록번호로 찾은 뒤):

| 결과 | 조건 | 화면 |
|---|---|---|
| `MATCHED` | 대표자 같음 + 상호 정규화 값 같음 | 다음 단계 |
| `NAME_CLOSE` | 대표자 같음 + 상호가 한쪽을 포함 | 다음 단계, 관리자 확인 표시 |
| `NOT_FOUND` | 등록번호 없음 | `다산동 명단에서 찾지 못했어요` + 다시 입력 / 문의 |
| `CEO_MISMATCH` | 대표자 다름 | `대표 공인중개사만 가입할 수 있어요` (소속 공인중개사 안내) |
| `SUSPENDED` | 상태 ≠ 영업중 | `휴업 중인 사무소예요` |
| `ALREADY_JOINED` | 이미 가입한 등록번호 | `이미 가입된 사무소예요` |

- 실패 메시지는 어느 칸이 틀렸는지 등록번호 존재 여부까지만 알려줌 (대표자 이름을 추측하게 두지 않음)
- 연속 5회 실패 시 10분 잠금 (목업 단계는 메모리)

## 6. 좌표

**VWorld 지오코더 약관상 결과를 저장할 수 없음** ("API 요청은 실시간으로 사용, 별도 저장장치·DB 저장 불가", 일일 40,000건). HANDOVER의 "좌표 저장"은 약관 위반이 된다.

대안: **주소만 저장하고, 지도는 서버가 그때 변환**
- `/api/office-map?office=<등록번호>` → 서버가 명단 주소로 getCoord → 정적 지도. 지금처럼 아무 좌표나 받지 않으므로 키 남용 통로도 사라짐
- 다산동 336곳·하루 매칭 수십 건이면 40,000건 한도와 거리가 멂
- 거리 표시(집주인 플로우 남은 것)는 같은 서버 변환으로 계산만 하고 숫자(km)만 내려보냄

## 7. 결정 (2026-10-25 대표님)

1. **소유 확인 = 확인 코드 전화** (토스 인증은 배포 후 계약되면 교체 검토)
   - 신청 완료 화면에 4자리 코드 + 확인 전화 안내 → 관리자가 **공개된 사무소 번호**로 전화해 코드 확인 → 승인
   - 신청자가 입력한 번호·명함·캡처는 위조 가능하므로 확인 근거로 쓰지 않는다
   - **안내는 모든 신청자에게 한 가지** (대표님 2026-10-25: 사무소마다 문구가 갈리면 복잡): 미리 안내 `가입 마지막에 브이월드·네이버 부동산에 등록된 사무소 번호로 확인 전화를 드려요`, 완료 화면 `사무소 번호로 확인 전화를 드려요` + `브이월드·네이버 부동산에 등록된 번호로 전화해요. 전화를 받으면 이 코드를 불러 주세요`. 가린 번호 표시·방문 안내는 두지 않는다
   - 관리자 내부 순서: ① 명단(브이월드) 번호 263곳(상호 안 번호 5곳 포함) ② 없으면 네이버 부동산에서 **등록번호가 같은** 광고의 번호 (네이버 광고는 등록번호 인증을 거쳐 사칭자가 바꿀 수 없음, 자동 수집은 약관상 금지라 수동 검색) ③ 둘 다 없으면 인증한 휴대폰으로 문자 개별 안내
   - 방문 확인은 하지 않는다 (담당자·중개사 모두 부담)
   - **확인 전화는 신청 후 48시간 안** (바로바로 못 함, 대표님 2026-10-25). 미리 안내·완료 화면 모두 48시간 명시, 승인되면 바로 집주인 의뢰를 보고 요청할 수 있다고 안내
   - 승인·반려 로직 `src/lib/broker/application.ts` (코드 일치, 개설 연도 1980~올해, 대기 중일 때만)
   - 한계: 대표가 아닌 직원이 받아도 코드를 알면 통과 → "그 사무소가 신청했다"까지 증명. 대표 본인 실명 확인은 토스 인증 단계에서
2. **서류 3종 업로드 → 명단 대조 + 확인 코드 전화로 교체** (명함·간판·캡처는 확인 근거가 못 됨)
3. **좌표: 주소만 저장, 보여줄 때 서버가 변환** (§6, 대표님 위임)
4. **개설 연도 배지: 숨기지 않고 등록일로 채움**
   - 숨기면 오래된 사무소(옛 형식 34곳 대부분)만 배지가 빠져 오히려 불리해진다
   - 표준 형식 298곳은 번호의 연도, 나머지 38곳은 관리자가 확인 전화 때 VWorld 중개업 조회의 등록일로 확인해 입력 (국토부 공공데이터 API에 등록일 필드가 있으면 자동화)
   - 구간 표시 그대로 (3년 미만 / 3~10년 / 10년 이상) — 10년 이상이 약 37곳이라 사무소 특정 위험 없음
