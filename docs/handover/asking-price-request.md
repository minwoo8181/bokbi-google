# 매물 수집기 요청: 매물 한 건 단위 호가 (복비 "실거래 · 호가" 그래프용)

> 매물 수집기(네이버 부동산 크롤링 프로그램) 세션에 그대로 붙여 넣는 요청서입니다. 2026-10-27 작성.
> 지금 받는 단지·평형 집계 CSV(`naver_complexes_*`, `naver_pyeongs_*`)는 **그대로 유지**하고, 아래 파일을 **하나 더** 만들어 주세요.

## 왜 필요한가

복비 분석 화면에 "평형 · 층 구간(저·중·고)별 지금 나온 매물 호가"와 "매월 호가 최저" 그래프를 넣으려 합니다.
지금 받는 자료에는 **단지 전체** 최저·최고 호가만 있어서, 평형·층별로 나눌 수 없습니다.

## 만들 파일

- 이름: `naver_listings_YYYYMMDD.csv` (같은 날짜의 `naver_complexes_*`·`naver_pyeongs_*`와 한 세트)
- 위치: `data/market/naver/`
- 인코딩: UTF-8 (BOM 있어도 됨), 쉼표 구분, 첫 줄은 열 이름
- 범위: 다산동 58개 단지 전부 (지금 집계와 같은 단지 목록)
- 주기: **매주 1번 같은 요일**(예: 월요일 오전). 지난 파일은 지우지 않고 쌓아 둡니다 (그래프가 이 기록으로 그려짐)

## 한 줄 = 매물 한 건 (동일매물 묶기 적용 후 대표 매물)

| 열 이름 | 예시 | 설명 |
|---|---|---|
| `observed_at_KST` | `2026-10-27 09:55` | 수집 시각 (파일 안에서 같아도 됨) |
| `naver_complex_no` | `110299` | 단지 번호 (지금 CSV와 같은 값) |
| `apt_name` | `e편한세상다산` | 단지 이름 |
| `article_no` | `2512345678` | 네이버 매물 번호 (대표 매물) |
| `trade_type` | `매매` / `전세` / `월세` | 거래 유형 |
| `pyeong_name` | `34A` | 평형(타입) 이름 — `naver_pyeongs_*`의 `pyeong_name`과 같은 표기 |
| `supply_m2` | `112.74` | 공급면적 |
| `exclusive_m2` | `84.96` | 전용면적 |
| `floor_raw` | `고/25`, `12/25`, `저/18` | 화면에 보이는 층 표기 **그대로** (가공하지 말 것) |
| `floor_num` | `12` | 숫자로 나오면 그 숫자, `고`·`중`·`저`로만 나오면 비움 |
| `floor_total` | `25` | 동 전체 층수 (있으면) |
| `price_manwon` | `140000` | 매매가 또는 전세 보증금 (만 원). 월세는 보증금 |
| `monthly_rent_manwon` | `150` | 월세만, 아니면 비움 |
| `confirmed_ymd` | `2026-10-21` | 확인매물 날짜 (있으면) |
| `same_listing_count` | `3` | 동일매물 묶기로 합쳐진 중개사 수 (없으면 1) |
| `dong_raw` | `104동` | 동 표기가 있으면 그대로, 없으면 비움 |

## 지켜 주실 것

1. **동일매물 묶기 적용 후** 한 건만 남겨 주세요 (지금 단지 집계와 같은 기준). 묶인 수는 `same_listing_count`에.
2. 층은 **화면 표기 그대로**(`floor_raw`)도 꼭 남겨 주세요. 저·중·고 구간 판정은 복비 쪽에서 합니다 (저층 1~3 · 중층 4~14 · 고층 15 이상, `고/25`처럼 숫자가 없으면 표기로 판정).
3. 가격은 **호가 그대로**. 협의 가능·급매 같은 문구로 숫자를 바꾸지 마세요.
4. 매물이 하나도 없는 단지도 빠뜨리지 말고 `naver_complexes_*`에는 지금처럼 0으로 남겨 주세요 (이 파일엔 줄이 없어도 됨).
5. 수집이 실패한 단지가 있으면 검증 리포트(`naver_집계_검증리포트_YYYYMMDD.md`)에 단지 이름과 이유를 적어 주세요.

## 확인 방법 (수집기 쪽 자체 점검)

- 단지별 `trade_type=매매` 줄 수 = 같은 날 `naver_complexes_*`의 `current_sale_listings`
- 단지별 매매 `price_manwon` 최저·최고 = 같은 날 `min_asking_price`·`max_asking_price`
- 평형별 매매 줄 수 = `naver_pyeongs_*`의 `current_sale_listings` 합

## 복비 쪽에서 하는 일 (참고)

- 평형(전용면적 ±1.5㎡) × 층 구간별 **호가 최저~최고, 매물 수, 기준일**을 계산해 "지금 나온 매물 호가" 줄에 표시
- 주마다 쌓인 파일로 **매월 호가 최저** 점선을 그림 (수집 시작한 달부터)
- 화면 문구는 "팔린 값 vs 부르는 값" · "지금 부르는 값" · "매물 n건 · 날짜 기준" (2026-10-27 확정). "입주민이 내놓은 가격"이라고 쓰지 않음 (누가 올렸는지 확인할 수 없음), 수집처 이름(네이버)도 화면에 쓰지 않음
- 받은 뒤 `npm run data:asking` (구현 [analysis.md](analysis.md) 실거래 · 호가 카드)
