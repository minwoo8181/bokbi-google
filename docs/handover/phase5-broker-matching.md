# Phase 5 ③~⑥ 중개사 승인 후 흐름 설계 (2026-10-25 대표님 확정)

> 가입·승인은 [phase5-broker-signup.md](phase5-broker-signup.md), 예전 피드 명세는 [phase5-agent-feed.md](phase5-agent-feed.md). 이 문서가 두 문서보다 우선한다.

## 1. 기준점
- 숨고 고수 앱: 받은 요청 → 견적 보내기(캐시 차감) → 고용됨. 비용이 든다는 걸 보내기 전에 알림
- 헤이딜러 딜러 앱: 목록 → 입찰 → 결과는 상태 배지 한 줄
- 복비: 집주인 "내 의뢰"처럼 한 건을 상태 배지로 보여 주고, 상태 규칙(`stage.ts`)을 양쪽이 같이 쓴다

## 3. 결정
1. **요청 노출 순서**: 집주인 화면은 도착 순서 유지, 약속 이행은 배지로만. 기록이 쌓이면 "방패 있는 사무소가 새 의뢰를 먼저 보기"를 검토(유료 자리는 점수 순서와 섞지 않고 `광고` 표시)
2. **크레딧**
   - 요청을 보낼 때 1개 차감, 선택받지 못해도 돌려주지 않는다 ("골랐을 때만 차감" 안 기각)
   - 계약 성사 보수는 하지 않는다 (중개보수 분배로 볼 위험)
   - MVP에는 결제·충전 버튼이 없다. 받는 방법 두 가지: ① 매주 월요일 3개까지 채움(쌓이지 않음) ② 광고 보고 받기 주 3번
   - ~~약속 지키면 +1 보상은 지금 고려하지 않는다~~ → **변경 (그릴링 2026-10-25)**: 복비 통해 계약 → 집주인 잔금 확인 → 후기 등록이면 그 의뢰에 쓴 크레딧 1개를 **자동으로 돌려받음** (별점 무관, 1번, 버튼 없음, 문구 `돌려받기`). `src/lib/deal/settle.ts`
   - 문구는 `받기`·`채워져요`. `무료`·`0원` 금지(`brokerCopy.test.ts`)
   - 가격 근거 기록: 크레딧을 다 쓴 사무소 비율, 광고 보고 받기 사용률, 매물당 요청·선택 수, 사무소별 선택 비율, 하루 요청 횟수를 다 쓴 날의 비율
3. **광고 보고 받기**: 애드센스 일반 광고·오퍼월로는 크레딧 지급 불가(일반 광고 보상은 정책 위반, 오퍼월은 콘텐츠 열기용). 구글 애드 매니저 웹 보상형 광고(`rewardedSlotGranted` 신호)로만 가능
   - 승인 전 화면 (C안, 대표님 확정 2026-10-25): 페이크 도어 버튼 `크레딧 더 받기 · 준비 중` → 누르면 한 문항 투표 `어떤 방법이 좋으세요?` (광고 보고 받기 / 사무소 소개하고 받기 / 지금도 충분해요) → `의견 고마워요. 열리면 알려 드릴게요`. 크레딧은 주지 않는다
   - 버튼 위치: 새 의뢰 피드에서 크레딧이 0개일 때(`크레딧이 없어요 · 월요일에 3개 채워져요`) + 내 사무소 크레딧 영역(항상)
   - 기록: 누른 사무소·횟수·누를 때 남은 크레딧·고른 답. 투표 결과는 화면에 보여 주지 않음(가짜 숫자 금지). 유료 선택지(이용권·충전)는 넣지 않음 — 가격은 중개사 인터뷰에서
   - 개발·테스트 스위처에서만 5초 가짜 광고로 받기 흐름·주 3회 제한을 미리 확인 (배포 전 제거)
   - 배포 후: 애드센스에 복비 도메인 추가·심사(누구나 볼 수 있는 홈·분석 화면 필요) → 애드 매니저(가입 완료) 승인 → "동영상이 아닌 광고 막기" 보호 설정 끄기 → 부동산 앱 업종 차단
   - 웹은 서버 검증이 없어 조작 가능 → 주 3회 제한으로 피해 한정
4. **강점 칩 "잘해요" 개편 (2026-10-25 대표님 A안, 구현)**: 22개 5분야(판매·홍보 / 협상·계약 / 소통 / 방문·일정 / 잘 아는 분야), 칩마다 짝이 되는 후기 칩(`brokerStrengths.endorsedBy`, 후기 칩 4개 추가해 28개) → 집주인 익명 카드에 `인정 n`(`endorsementCount`) + `중개사가 고른 강점이에요`. 누구나 하는 조건(주말·저녁 안내, 집주인 없이 안내, 전자계약, 카톡 상담, 영상 촬영)은 `가능한 것`(가입 때 여러 개, 카드에 `가능 …` 한 줄). 아래는 이전 결정
   **강점 칩 요청마다 바꾸기**: 가입 때 고른 3개가 기본. 확인 시트 3층 = 보낼 강점 3칸 / 이 매물에 추천 3~5개(매물 정보 고정 규칙: 세입자 거주 → 세입자 일정, 전세 → 전세대출, 빈집 → 사진) / 전체 보기(분야별 접기). 매물 맞춤 칩 8개 추가(18 → 26개)
5. **집주인 정보 공개**: 매칭되면 동·호수·집주인 연락처 공개 (집주인 동의 화면 제3자 제공 항목에 이미 포함)
6. **소유자 확인 (광고 등록 앞)**
   - `광고 시작 전에 등기부등본으로 소유자 확인을 먼저 진행해 주세요.`
   - `[소유자 확인했어요]` → 광고 링크 입력
   - `소유자가 달라요 >` → `집주인에게 전화로 확인해 주세요` + `[집주인에게 전화]` `[확인됐어요]`(→ 광고 링크 입력)
   - 맨 아래 작은 링크 `허위 매물 같아요` → 관리자에게 넘어가 관리자가 의뢰를 멈춤, **크레딧은 돌려준다고 안내**
   - 위임장 문구·"확인 중" 상태·광고 기한 멈춤은 두지 않는다
7. **방문 일정** (2026-10-25 변경): 화면 예약 확정 대신 전화로 정해 저장 + 양쪽 캘린더 저장, 취소는 전화로 알리면서(기록 남김). 다른 중개사 일정은 누구인지 숨김. 상세 §5-1 ⑤
8. **계약일 보고 늦을 때**: 약속 이행 기록에 쌓이지 않는 것만 (추가 불이익 없음)
9. **목업 저장소**: 집주인·중개사가 같은 저장소를 읽고 써서 한 브라우저로 양쪽 흐름을 끝까지 시험. 테스트 스위처는 배포 전 제거

## 5-2. 거래 페이지 (그릴링 2026-10-25, ⑥ 계약 보고를 대신함)

**구조**: 집 하나 × 중개사 하나 = 거래 페이지 하나. 위는 시간순 기록, 맨 아래는 지금 할 일 카드 한 장. 집주인은 중개사 3곳 목록 → 한 곳 페이지, 중개사는 매칭된 집 목록 → 한 집 페이지. 목록 카드 아래 색 띠(빨강 기한 / 파랑 내가 확인할 것 / 노랑 24시간 안 / 초록 다음 일정 / 회색 끝남, 겹치면 이 순서). 중개사 `지금 할 일` 목록은 색 띠로 합침

**확정 규칙**
- 중개사가 알리고(가계약·계약 완료·잔금 완료·해제) 집주인이 `맞아요`/`아니에요`. 확인 전엔 자동으로 바뀌는 것 없음. 동시에 누르기는 하지 않음
- 가계약 생략 가능, 중도금 없으면 기록 안 함. 계약 보고엔 계약일, 잔금 보고엔 잔금일 필요
- 날짜는 한 번에도 따로도. 바꾸면 기록 한 줄. **캘린더 저장 안내는 날짜가 정해진 순간**(양쪽 `캘린더에 모두 저장`), 당일엔 `잊지 않으셨죠?` 확인만
- 집주인이 한 곳의 가계약(또는 바로 계약)을 확인하면 나머지 정리: 광고 내려 달라는 요청(`광고 내렸어요` → 집주인 `광고 내림 확인 n/m`), 앞으로 잡힌 방문 자동 취소(`SYSTEM`, 양쪽 캘린더 안내), 크레딧 환불 없음. 이긴 곳이 나중에 깨져도 되살리지 않음 → 집주인 `다시 매칭 요청`
- `아니에요`: 기록 남음, 단계 그대로, 중개사에 `전화로 확인해 주세요`
- 거래 완료 = 잔금 확인. 이후 후기 → 크레딧 1개 돌려받기(⑥)
- 서류 안내는 중개사 화면에만 (초안 → 대표님 검수)
- 다른 사람에게 영향을 주는 버튼은 확인 창에 결과를 지금 상태로 계산해 보여 줌(해당 없는 줄 빼기). 중개사 확인 창엔 다른 중개사 이야기 없음(블라인드)
- 모션 5가지 (DESIGN.md §6)

**구현 순서**: ① 규칙·테스트·모션 토큰 **(완료 2026-10-25)** → ② 중개사 거래 페이지 + 내 매물 색 띠 (③ 서류 초안 병행) **(완료 2026-10-25)** → ④ 집주인 목록 + 중개사별 거래 페이지 **(완료 2026-10-25)** · ⑥ 계약 완료 카드 합치기 + 후기 → 크레딧 돌려받기 + 약속 이행 **(완료 2026-10-25)** → ⑤ 가계약 정리·광고 내림 → ⑥ 계약·잔금 확인 → 후기 → 크레딧 돌려받기
